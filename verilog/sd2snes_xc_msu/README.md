# Xeno Crisis on sd2snes: the MSU-1 core (`sd2snes_xc_msu`)

A second core plays the music from an MSU-1 pack (for example one made from the official soundtrack) instead of decoding the game's Opus streams. It is picked automatically: when `<rom>.msu` exists next to the ROM and `/sd2snes/fpga_xc_msu.bi3` is on the card, `load_rom()` loads `fpga_xc_msu.bi3` (`xc_msu_pack()` in `xc_load.c`); otherwise `fpga_xc.bi3`, unchanged. The same `xc_soc.bin` serves both. Track numbers, lengths and what pack makers need to know: [`MSU1_PACK.md`](MSU1_PACK.md).

- **FPGA:** this folder is its own Quartus project (`sd2snes_xc_msu.qpf`; `make` gives `fpga_xc_msu.bi3`, like the other cores). Like `sd2snes_sgb_msu`, it takes the shared sources from its base core, `../sd2snes_xc`: the soft CPU, `main.v`, `mcu_cmd.v`, the IP. Its own files are `msu.v`, `xc_dac.v`, `xc_msubox.v`, `main.qsf` (the Opus core's, with the shared paths, `XC_MSU` and a search path to `../sd2snes_xc`) and `main.sdc` (a copy of the Opus core's; keep them the same). With `XC_MSU`, `xc_top` (`MSU = 1`) has `xc_msubox.v` in place of the Opus decode mailbox, at the same soft CPU address: `CTRL` bit 3 reads 1, a write to `+0x10` is an MSU-1 register write (`$2000 + n`), `+0x14` reads the MSU-1 status byte. this folder's `msu.v` gets its register writes from there (the SNES does not see the MSU-1; the MCU clears `FEAT_MSU1`) and has no data buffer (`XC_MSU`: the game has no MSU-1 data, which saves 16 M9K). `xc_dac.v` is `dac.v` with linear interpolation instead of the 3-stage CIC (about 520 LUTs + 4 DSP multipliers instead of about 1,600 LUTs); same buffer, MCU interface, 44.1 kHz timing, volume ramp and I2S output. Net, the MSU-1 core needs about 500 LEs more than the Opus core and 6 M9K fewer.
- **Soft CPU** (`socfw/xc_mix.c`, "MSU-1 mode"): the game's music position still advances at the same pace (packets are counted as decoded, nothing is sent to the MCU), so the game's end-of-track and loop logic and everything core 0 sees stay the same; the music is not mixed into the BRR stream, the sound effects are. When the game starts a track from its beginning, the mixer requests MSU-1 track n (n = the stream's number in the firmware's table). A track the game loops onto itself plays with MSU-1 repeat; an intro plays once and its loop part starts as soon as the intro `.pcm` has played out, however long the game's own intro is; a self-loop does not restart the `.pcm`. Pause and resume map to the MSU-1 play bit, a reset stops the MSU-1, a missing `.pcm` is silent. The mixer waits for "audio busy" to clear before it writes the control register.
- **MCU:** the usual `msu1_loop()`, with two changes for Xeno Crisis. It checks the save RAM every second even while music plays (other MSU-1 games only save while the MSU-1 is idle, and Xeno Crisis nearly always plays music) and regardless of the MSU-1 autosave setting, because this is the game's only save path while it runs. During that CRC and the save, `xc_audio_service()` (already called between their sectors for the Opus service) refills the MSU-1 audio buffer (`msu1_audio_service()`). Both MCUs: on the LPC1756 (`firmware.im3`), which can't decode Opus, this is the way to get music.
- **Tests:** MesenCE routes the soft CPU's MSU-1 registers to its MSU-1 emulation when a `.msu` is next to the ROM (`XC_MSU=0` forces the Opus mode). With a pack of test tones, the logged register writes and the recorded audio show: the voiced intro played once, the title with repeat, in-game intro then its loop part (started when the 1.5 s intro tone ended, not restarted when the game reached its loop), pause and resume, a missing track silent, a missing or empty intro followed by its loop part, stop at reset; the Opus mode is unchanged (0 underruns). `fpga/msutest/tb_msu.v` checks `xc_msubox` + `msu.v` + `xc_dac.v`: register writes and status, "audio busy" handling, 44.1 kHz input rate, interpolated output with the same level and channel order as `dac.v` (the same testbench runs on `dac.v`). Not tested: the fit and timing in Quartus, and hardware.

Everything else (the soft CPU, the memory layout, the loader, performance) is as in [`../sd2snes_xc/README.md`](../sd2snes_xc/README.md).
